# Запуск: GitHub → Netlify + Supabase

Подготовлено 28 сентября 2026. Проекты и аккаунты автоматически не создавались. В комплекте обычный HTML/CSS/JavaScript: Node, npm и платные API для работы книги не нужны.

## 1. Сначала посмотреть

Распакуй весь архив. Открой терминал в этой папке и выполни `python start.py` (Windows: `py start.py`). Книга: `http://localhost:8000`, мастерская: `http://localhost:8000/admin.html`.

Отдельный `kniga-demo.html` — автономное читательское демо. В нём доступны все главы, нет облачной записи и редактора. Полная мастерская находится в архиве.

## 2. Supabase — база, файлы, вход автора

1. Создай проект на https://supabase.com/dashboard . Сохрани пароль базы у себя; на сайт он не вставляется.
2. В SQL Editor выполни `supabase/schema.sql` **один раз на новом проекте**. Затем выполни `002_reading_stats.sql`, после него `003_publish_atomic.sql` и `004_ending_choice.sql` и `005_finale.sql`.
3. Если предыдущая схема из исходного архива уже установлена, **не запускай schema.sql повторно**: выполни только 002, 003, 004 и 005. Они рассчитаны на повторное применение.
4. В Authentication → Users создай своего пользователя автора с email и паролем. Скопируй его User UID. Публичную регистрацию пользователей отключи: читательнице регистрация не нужна.
5. В SQL Editor выполни, заменив строку UUID реальным значением:

```sql
insert into public.book_owners(book_id, owner_id)
values ('kniga', 'ВСТАВЬ-UUID-АВТОРА')
on conflict (book_id) do update set owner_id = excluded.owner_id;
```

6. Возьми Project URL и **publishable key** в настройках проекта / API Keys. Для старого проекта допустим `anon` key. `sb_secret_…`, `service_role`, пароль базы и пароль автора **не должны попадать в config.js/GitHub/HTML**.
7. В `site/config.js` укажи:

```js
window.BOOK_CONFIG = {
  url: 'https://ТВОЙ-ПРОЕКТ.supabase.co',
  key: 'ТВОЙ-PUBLISHABLE-ИЛИ-ANON-KEY',
  bookId: 'kniga'
};
```

Можно заполнить эти поля в мастерской → Подключение, скачать config.js и заменить им `site/config.js`. Публичный ключ предполагает использование в браузере; права защищаются RLS и владельцем книги.

**Что создаётся:** publications — опубликованная книга; drafts — закрытый черновик; revisions — версии; book_owners — назначение автора; reading_sessions — закрытая статистика. Бакет book-drafts закрыт, book-published содержит опубликованные вложения. Файлы книги без входа доступны читателю по ссылке; это не парольная защита опубликованного текста.

## 3. GitHub

1. Создай **приватный** репозиторий, например `kniga-aya`.
2. Загрузи распакованные файлы проекта так, чтобы в корне были `netlify.toml`, `site`, `supabase`, `README.md`. Не загружай сам ZIP вместо исходников.
3. Не добавляй JSON-резервные копии мастерской, архивы переписки, пароли и личные неотобранные файлы. `.gitignore` уже исключает резервные копии и `.env`.
4. Сохрани изменения в `main`.

Не нужно повторно переносить в GitHub фотографии, которые позже добавишь через мастерскую: они сохраняются в Supabase.

## 4. Netlify

1. Открой https://app.netlify.com/ → **Add new project → Import an existing project → GitHub**.
2. Разреши Netlify доступ к выбранному репозиторию и выбери его.
3. Production branch: `main`. Base directory: пусто. Build command: пусто. Publish directory: **site**. Настройки уже заданы в `netlify.toml`.
4. Запусти Deploy. Открой выданный Netlify адрес. Публичные URL и ключ уже находятся в config.js; переменные VAPID, service_role или OpenAI этому проекту не нужны.
5. Открой `https://АДРЕС-САЙТА/admin.html`, войди аккаунтом автора. Проверь главы, нажми **Сохранить**, затем **Опубликовать**.
6. Открой книгу в отдельном браузере/приватном окне. Это должен быть опубликованный вариант. Изменения текста, медиа, цветов и декора после публикации не требуют нового деплоя кода.
7. Открытая читательская вкладка не опрашивает публикацию и не перезагружается. Новая редакция загружается при следующем открытии сайта. Текущая закладка сохраняется.

Если старый сайт уже работает, сначала создай отдельный тестовый Netlify-проект или preview-ветку. Не заменяй старую публикацию до проверки новой.

## 5. Как узнать, открывали ли книгу

Мастерская → **Чтение**:

- число зарегистрированных открытий и анонимных браузеров;
- первый и последний момент сеанса;
- последняя открытая глава, страница и устойчивый ID блока;
- время активной вкладки, тип устройства, ОС и браузер (приблизительно по User-Agent);
- экспорт CSV и очистка статистики.

При первом открытии читатель выбирает, разрешать ли эту статистику. В настройках можно отключить. Без разрешения запись не ведётся. Предпросмотр автора всегда исключён; открытие мастерской помечает текущий браузер как авторский. Снимай исключение только для своего теста. Данные отправляются при смене страницы и периодически, пока вкладка активна. При закрытии вкладки последние секунды могут не успеть сохраниться.

Это **не подтверждение «Айя прочитала»**: один человек может пользоваться несколькими браузерами, ссылку можно переслать, а открытая страница не означает прочтение. Нет IP, геолокации, email или скрытого распознавания человека. Без Supabase доступны лишь записи текущего браузера. Анонимные события могут быть неточными и не предназначены для доказательств.

## 6. Мастерская

| Что меняешь | Где |
|---|---|
| Название, автор, посвящение, записка, обложка, музыка | Обложка и оформление |
| Шапка, подписи, ChocoBubble Text и дополнительные варианты шрифта, интервал, движение, плотность | Стиль и детали |
| До 6 стикеров на главу, размер, поворот, прозрачность | Стиль и детали |
| Полный текст, порядок, название, настроение, фон/акцент главы | Главы и текст |
| Фото/аудио/видео/скриншоты, подписи, положение и удаление слотов | Наши воспоминания |
| Картинка главы, загрузки до 500 файлов/папки/ZIP, теги, закрепление | Декор |
| История версий, восстановление в черновик, резервная копия | Версии и экспорт |
| Посещения, главы и последние страницы | Чтение |

До 20 МБ на файл, 250 МБ на подборку, 500 изображений. ZIP: обычный ZIP со сжатием Deflate или без сжатия, без пароля. Повторно выбери прерванную подборку — хеши уже загруженных файлов не дадут создать дубликаты. Большие видео предварительно сожми. Источник и теги заполняются вручную; ИИ не имитируется.

## 7. Обязательная проверка после подключения

- Войти автором, изменить одно слово, сохранить, перезагрузить мастерскую: правка осталась.
- Опубликовать, открыть с другого устройства: правка появилась. Затем вернуть тестовое слово.
- Загрузить фото, опубликовать, открыть его с другого устройства.
- Разрешить статистику в отдельном браузере, перелистнуть пару страниц, через 15–30 секунд обновить раздел Чтение.
- Проверить запросы неавторским аккаунтом: нет доступа к черновикам, версиям и статистике; попытка публикации отвергается.
- Проверить iPhone/Safari: листание, крупный текст, аудио, возврат к месту чтения. В данной работе проверялся Chromium с мобильными размерами, не физический iPhone.
- Скачай резервную копию перед большой правкой. Локальное хранилище может очищаться браузером.

## 8. Если не работает

**Локальные правки не видны ей:** заполни config.js, выполни SQL, войди и опубликуй. Локальная публикация не переносится между устройствами.

**«Не назначен автором»:** сравни User UID и запись book_owners. Нужен пользователь Authentication, не email вместо UUID.

**Статистика пуста:** проверь миграцию 002, первую публикацию, согласие читателя и исключение авторского браузера. Пусто не означает, что никто не открывал сайт.

**Конфликт версии:** скачай резервную копию введённого текста; не перезаписывай более свежую редакцию вслепую. Проверь другой открытый редактор.

**Ошибка загрузки:** поддерживаемый формат, размер до 20 МБ, назначение владельца, оба бакета и политики из SQL.

**Netlify 404:** publish directory должна быть `site`, а не корень проекта. В site должен лежать index.html.

**Предупреждение о секретах:** проверь, что случайно не загружен secret/service_role key. Не отключай сканирование секретов ради прохождения сборки.

## Финальная глава по новому ТЗ

После миграций настрой и опубликуй финал в админке. Открой «Финальная глава → Читательский доступ → Создать читательскую ссылку». Передай эту одну ссылку. Выбор хранится в Supabase и действует на разных устройствах. Обе сцены меняют только режим книги, а не удаляют внешние аккаунты, Netlify, GitHub или файлы. Подробности и проверки: **FINALE.md**. Серверные service_role/Netlify/GitHub-токены для этой версии не нужны.
